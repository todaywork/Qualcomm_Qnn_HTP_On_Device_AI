# HTP V73 一键检测包

双击 check_htp_adb.bat 即可。将整个 qnn_htp_probe_v73 文件夹复制到其他位置或 Windows 电脑后仍可使用，无需安装 QAIRT SDK 或配置 ADB 的 PATH。

目录结构：
- check_htp_adb.bat：检测入口。
- tools/adb/：随包提供的 Windows ADB 及 DLL。
- runtime/bin/：Android qnn-platform-validator。
- runtime/lib/：来自原 htp_verify_staging 的 Android 运行库。
- runtime/dsp/：来自原 htp_verify_staging 的 V73 DSP 依赖。
- probe_logs/：运行后生成的检测日志与报告。

使用条件：Windows 自带的 PowerShell 可用；Android 设备已开启 USB 调试并授权当前电脑；电脑能够通过 ADB 识别设备（必要时安装设备 USB 驱动）。当前 DSP 资源适用于 HTP V73。

## PASS 证明什么？

**PASS 表示：在当前 ADB shell 身份、设备系统和运行库环境下，CPU 能通过 FastRPC 调用 DSP，并成功完成一次 Calculator 求和测试。**

它证明了：

- DSP 可访问，能查询到其架构版本。
- 测试所需的库能够加载。
- CPU 与 DSP 的基础通信及简单计算链路可用。

**PASS 不等于 NPU 模型推理已验证。** 本次测试没有运行神经网络模型，不能据此确认完整 QNN HTP 初始化、模型执行、输出正确性或 APK 内可用。

可直接引用的结论：

> 设备的 DSP 访问与基础计算链路已验证通过，具备进一步验证 QNN HTP/NPU 推理的基础条件。

## 下一步：验证设备能否进行 NPU 推理

**在目标设备上，使用 qnn-net-run 显式指定 libQnnHtp.so，实际运行一个模型并核对输出。**

1. 准备模型、输入和预期输出。当前 V73 设备可优先复测已有的 MobileBERT DLC：上级 htp_verify_staging/model 和 input 中已有资源，历史记录中的输出为 token_id=1996。这个预期值仅适用于配套的原始输入。
2. 准备同版 QAIRT 的 qnn-net-run 和运行库，使用目标架构对应的 Stub/Skel。本一键包仅包含 validator 检测工具，模型推理所需的 qnn-net-run、模型和输入需另行准备。
3. 通过 ADB shell 运行 qnn-net-run，明确指定 --backend 指向 libQnnHtp.so，并传入 DLC、输入列表和输出目录；检查日志确实使用 HTP 后端，完成模型加载、图准备及执行。
4. 检查进程成功退出、输出文件生成，并与预期结果对比。仅退出码为 0 或仅产生输出文件还不足以证明结果正确。

通过后可以表述：

> 该设备在当前系统和 QAIRT 版本下，已通过 QNN HTP 后端完成该模型的推理，且输出校验通过。

这验证的是该模型在当前环境下可用，不代表任意模型都支持。若目标是在 APK 中使用，还需要在 App 内完成 Native HTP 初始化及同一模型推理验证。

## 切换到 V68

以下源文件均应来自同一个 QAIRT SDK 版本，本机来源为 E:\QualComm\AIStack\QAIRT\2.46.0.260424。

1. runtime/lib 增加或替换为 lib/aarch64-android/libQnnHtpV68CalculatorStub.so；完整 HTP 配套还需 libQnnHtpV68Stub.so。本包已经包含 V68Stub，但缺少 V68CalculatorStub。
2. runtime/dsp 整体换成 SDK 的 lib/hexagon-v68/unsigned 下的文件。最直接参与 validator 测试的是其中的 libCalculator_skel.so；完整配套还包括 libQnnHtpV68Skel.so 等。即使文件名不含架构，也应取自 V68 目录，不要重命名 V73 文件。
3. BAT 中将本地依赖检查列表里的 libQnnHtpV73Stub.so、libQnnHtpV73CalculatorStub.so、libQnnHtpV73Skel.so 改为对应 V68 名称，同时更新 V73 提示文字。
4. 同为 arm64 Android 且同一 SDK 版本时，runtime/bin/qnn-platform-validator、通用 Android 库和 tools/adb 不需要因 V73 -> V68 更名。若升级 SDK，应整套更新配套运行库，避免混用。
5. 命令仍使用 --backend dsp；当前命令不需要添加 --arch v68。以目标设备查询到的 Core Version 和单元测试结果确认架构及可用性。

本次仅验证了 V73 实机；V68 资源路径已在本机 SDK 中核对，尚未在 V68 设备验证。

依据：SDK docs/QAIRT-Docs/QNN/general/tools.html 的 qnn-platform-validator 节，列出 Android validator 所需的工具、架构对应 CalculatorStub 和 libCalculator_skel.so；本包保留完整 staging 运行库，超出该最小资源集合。
