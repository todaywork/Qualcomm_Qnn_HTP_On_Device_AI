# NPU 模型一键检测包（HTP V73）

双击 check_npu_model.bat 即可。请复制整个文件夹使用，不能只复制 BAT。

## 一键执行内容

1. 检查随包依赖和已授权的 Android 设备。
2. 删除固定设备目录 /data/local/tmp/qnn_npu_model_probe，重建并推送资源；清理失败就停止。
3. 使用 libQnnHtp.so 执行两组 Conv2d + ReLU 模型推理。
4. 使用 libQnnCpu.so 执行同一个量化模型，生成对照输出。
5. 下载本次输出，检查两次推理完成记录与后端信息。
6. 逐元素比较输出并显示 PASS/FAIL。

本机日志按时间保存在 probe_logs。设备端使用固定目录，下次运行时清空；请勿同时对同一设备启动多个检测。不会清理基础 validator 的设备目录。

## PASS 证明什么

**当前设备在当前系统和随包 QAIRT 环境下，能通过 QNN HTP 后端执行这个量化神经网络模型，且输出与 CPU 对照在设定容差内一致。**

这比 validator 的 Calculator 求和测试多验证了模型图的构建、准备和执行。它不代表所有模型都兼容，也不代表 APK 身份下可用，未评估长期稳定性、功耗或模型业务精度。

比较标准：每组输出 710432 个 float32 元素，尺寸正确、数值有限，全部元素绝对误差不超过 0.109418（两个输出量化步长加浮点余量）。这是本样例的冒烟测试标准，不是通用精度标准，也不是逐位一致。CPU 对照失败时整个检测也会失败，具体原因看日志；FAIL 不自动等于硬件不支持 NPU。

## 使用方式

电脑需要 Windows x64；设备需开启 USB 调试并授权，USB 驱动需能正常识别设备。ADB 已随包提供，Python 3.10 已随包提供，不需要另行安装 Python、NumPy、NDK 或 QAIRT SDK。

```bat
check_npu_model.bat
check_npu_model.bat -DeviceSerial AN3GUT4220011858
check_npu_model.bat -DeviceSerial AN3GUT4220011858 -NoPause
```

无序列号时要求只有一台可选设备。-NoPause 用于自动化，退出码 0 为通过，1 为未通过。

## 目录

- check_npu_model.bat：双击入口。
- run_probe.py：部署、执行、下载与结果比较逻辑。
- tools/adb：adb.exe 及两个 DLL。
- tools/python：随包 Python 3.10 运行时；检测仅用标准库。
- runtime/bin：qnn-net-run。
- runtime/lib：Android QNN 运行库，含 HTP、CPU、Prepare、V73 Stub 等。
- runtime/dsp：V73 DSP 配套资源。
- model/libconv_relu_quantized.so：已编译的 Android arm64 模型库，363304 字节。
- inputs：两组 float 输入及相对路径输入列表。
- probe_logs/时间戳：设备信息、部署日志、HTP/CPU 日志、输出、comparison.json、result.json。失败时含 error.txt。

## 资源与实测

QAIRT 2.46.0.260424，模型来自 SDK 的 qnn_model_8bit_quantized.cpp/.bin，使用 Android NDK r27c 编译。输入 [1,299,299,3]，8 位量化 Conv2d + ReLU，输出 [1,149,149,32]。qnn-net-run 将 float 输入按模型量化参数转换，输出保存为 float。

2026-09-11 在 MAA-AN10 / SM8550 / V73 实测 PASS，两组最大绝对误差约 0.10941744 和 0.10941720，超容差元素数均为 0。当前包只针对 V73 验证；V68 需要替换配套 DSP/Stub 资源并重新实测。

CPU 日志中的线程 affinity 回退警告在本次测试中未阻止执行。判断以执行返回状态、元数据和输出比较为准。
## 控制台字段说明

- Sample 0 / 1：第 1 / 2 组输入，每组分别执行 CPU 和 NPU 推理，不是 CPU/NPU 的编号。
- max error：该组所有输出元素的最大绝对差 |NPU - CPU|。
- tolerance：允许误差上限 0.109418。
- mismatches：超过容差的元素数量；0 表示均在容差内，不表示逐位相同。
- output_cpu/Result_0、Result_1：CPU 原始输出。output_htp/Result_0、Result_1：NPU 原始输出。

BAT 仅调用随包 Python；检测与比较逻辑全部在 run_probe.py，不再使用 PowerShell 脚本。

判定规则：最大绝对误差 <= 0.109418 且超标元素数为 0 时，该组输出比较通过；最大误差 > 0.109418（即至少一个元素超标）则不通过。两组均通过且推理完成检查通过，最终才显示 PASS。误差是输出数值的绝对差，不是百分比。

## 为什么阈值是 0.109418？

模型最终输出的量化 scale 为 0.0547085，相邻量化值之间相差一个这样的步长。本脚本选用两个输出量化步长，加 0.000001 浮点比较余量，因此阈值为 2 × 0.0547085 + 0.000001 = 0.109418。

允许两个步长是本样例选定的冒烟测试标准，用来容纳不同后端量化计算与舍入的差异；不是 SDK 官方规定，也不是经过证明的误差上界。实测在此范围内不代表所有输入都一定在此范围内。阈值是绝对差，不是百分比；更换模型或精度要求时应重新确定。控制台保留原单行结果，并在其后打印含义、阈值来源及判定规则。
