# Android HTP 探针使用说明

本目录提供 Windows 主机通过 ADB 检查 Android arm64 设备 DSP/HTP 基础链路的脚本和运行资源。选择包时以设备实际 Hexagon 架构为准，不能只看产品目录名称。

## 1. 现有检测包

| 目录 | 目标架构 | 本次资源来源 | 状态 |
| --- | --- | --- | --- |
| SA8255_V73 | V73 | QAIRT 2.46.0.260424 | 原参考包，ADB 入口已改用系统 PATH |
| SA8295_V68 | V68 | QAIRT 2.46.0.260424 | 新建包，资源校验通过，尚未通过 V68 实机验证 |

V68/V73 是硬件架构，QAIRT 版本是软件发行版本，两者不是同一个概念。当前包使用上述版本，不代表只能使用该版本；后文的生成脚本接受任意已安装 SDK 路径，并检查其是否具备所需资源。

这些包面向 Android aarch64，不适用于 QNX。运行探针不要求 Windows 安装完整 QAIRT，但需要 PowerShell、已连接并授权 USB 调试的 Android 设备。检测统一使用 Windows 主机 PATH 中的 adb.exe。

## 2. 快速运行

在本说明所在目录打开 PowerShell：

```powershell
# 查看新包帮助、校验文件；这两步不访问设备
.\SA8295_V68\check_htp_adb.bat --help
.\SA8295_V68\check_htp_adb.bat --check-files

# 先查看设备序列号
adb devices -l

# 将 V68_DEVICE_SERIAL 替换为实际 V68 设备序列号
.\SA8295_V68\check_htp_adb.bat V68_DEVICE_SERIAL --no-pause
```

只有一台设备时，可直接双击 `SA8295_V68/check_htp_adb.bat`，或省略序列号运行。多设备时必须指定序列号。`--no-pause` 适合终端及自动化调用。

`--check-files`、架构预检查和以下新日志规则适用于新 V68 包及生成器新建的包；原 V73 脚本保持原有行为，不应直接套用新参数。

## 3. 新包的结构与检测范围

- `runtime/bin`：Android 平台验证程序。
- `runtime/lib`：Android 主机侧 QNN 库，以及目标架构的 Stub、CalculatorStub。
- `runtime/dsp`：来自目标架构 `unsigned` 目录的 DSP 资源。
- 旧包若仍有 `tools/adb`，属于历史附带文件，检测不再使用；新生成的包不包含该目录。
- `bundle_manifest.json`：SDK 版本、构建号、文件来源、大小和 SHA-256。
- `verify_bundle.ps1`：校验资源完整性、架构及未登记文件。
- `probe_logs/<运行时间>/`：设备信息、架构查询、执行输出和结果。

新脚本先检查连接和 Android arm64 ABI，部署后运行 `--coreVersion` 查询。只有查询成功且实际架构与包一致，才继续执行 DSP Calculator 测试。退出码为 0、实际架构匹配且出现 DSP 单元测试成功标记时，才报告 PASS。

V68、V73、V75 及后续生成的检测脚本统一使用设备固定目录 `/data/local/tmp/qnn_platform_probe`。每次部署先检查该目录不是符号链接，且 `/data/local/tmp` 的规范路径符合预期，再删除固定目录、重新创建 bin/lib/dsp/validator_output 并 push。清理或创建失败就停止，不继续推送。检测结束后保留本次设备文件，下次运行时清理；电脑上的 probe_logs 仍按时间分开保存。同一设备上不要同时运行多个检测脚本，以免相互清理。之前生成的带时间戳设备目录不会由此自动删除。

| 结果 | 含义 |
| --- | --- |
| 本地文件校验 PASS | 资源与清单一致，不代表设备可用 |
| `ARCH_MISMATCH_OR_UNCONFIRMED` | 查询失败、架构不符或输出无法确认；未继续运行单元测试 |
| 设备测试 PASS | 本次设备与资源组合的 DSP Calculator 基础链路通过 |
| `INCOMPLETE` 或其他失败 | 根据连接、部署及 validator 日志定位问题 |

单独的 library version `Not Found` 不等同于计算测试失败；应结合架构、退出码和 DSP 测试结果判断。失败时检查依赖库、DSP 搜索路径、设备固件、FastRPC、权限及签名策略，不要仅通过替换文件名绕过架构检查。

Calculator 通过说明基础 DSP 通信与计算链路可用，不代表任意模型、算子或完整应用均可运行。模型验证仍需同版本 QNN 工具、匹配架构的模型或 context、明确的输入及参考输出；性能必须在目标实机测量。

## 4. 更换 QAIRT 版本或目标架构

双击本目录的 `build_probe_bundle.bat`，或在终端运行：

```powershell
.\build_probe_bundle.bat
```

启动后会先打印可用示例和默认参数。按提示逐项输入；留空直接回车使用方括号中的默认值，连续按四次回车即可使用全部默认值。

| 提示 | 示例 | 说明 |
| --- | --- | --- |
| SdkRoot | `E:\QualComm\AIStack\QAIRT\2.46.0.260424` | 默认使用该 SDK 根目录，可输入其他已安装版本 |
| HtpArch | `75` | 默认 75，可输入 68、73 等两位数字 |
| OutputDirectory | `BAT所在目录\HTP_V75_时间戳` | 默认在 BAT 所在目录生成 HTP_V75_时间戳；手动输入须为新目录或空目录 |
| TargetLabel | `HTP_V75` | 默认 HTP_V75；会随输入的架构调整，如 HTP_V68 |

路径可包含空格，无需额外加引号。架构由 HtpArch 决定，标签不会改变真实设备架构。完成或失败后窗口暂停，方便查看结果。

BAT 是单文件入口，内部调用 Windows 自带 PowerShell 完成复制、SDK 元数据读取和 SHA-256 校验，不再依赖旧的 `build_probe_bundle.ps1`。生成器使用 `SA8295_V68` 内的检测 BAT 和校验脚本作为模板，请保留该目录。

生成时不需要连接设备，不查找或复制 ADB，也不再提供 AdbDirectory 参数。运行检测时，Windows 主机须能通过 PATH 找到 `adb.exe`。可先执行 `where.exe adb` 和 `adb devices -l`。若不存在，请将已安装的 Android platform-tools 目录加入 PATH；脚本不会回退使用本目录里的 ADB。

生成器从 `sdk.yaml` 读取版本和构建号，预检必要资源，再复制并核对 SHA-256。资源对应关系为：

| 资源 | SDK 内相对路径 |
| --- | --- |
| validator | `bin/aarch64-android/qnn-platform-validator` |
| 主机侧通用库 | `lib/aarch64-android/` |
| 目标 Stub | `lib/aarch64-android/libQnnHtpV<架构>Stub.so` |
| Calculator Stub | `lib/aarch64-android/libQnnHtpV<架构>CalculatorStub.so` |
| DSP 资源 | `lib/hexagon-v<架构>/unsigned/` |

DSP 资源必须来自真正的目标架构目录，包括名字不带架构的 `libCalculator_skel.so`。不能把 V73 文件改名为 V68。只复制 SDK 实际提供的 DSP 文件，不要求每个版本都具有相同数量的文件或 `.cat` 文件。

缺少必要资源时生成器报错停止；这可能是本地 SDK 安装不完整，也可能是该发行包不提供该平台/架构组合。更换版本后仍应查看其 validator 帮助和发行说明；命令参数或输出格式变化可能需要调整脚本，生成成功不等于任意 SDK 均具备运行兼容性。

## 5. 当前只有 V73 设备，能否仿真验证 V68？

有官方 QNN HTP QEMU 仿真方案，可在 Linux x86_64 主机上运行 V68 HTP 推理，不需要汽车硬件。但普通 Android 模拟器、普通 Linux 虚拟机本身并不具备此能力，必须安装匹配的 Hexagon QEMU、Hexagon SDK 和 QNN 运行资源。Windows 上使用 Linux 虚拟机作为宿主的完整配置尚未在本机验证。

本地 QAIRT 2.48.40.260702 官方文档 `docs/QAIRT-Docs/QNN/general/htp/htp_auto_qemu.html` 明确说明：

- 此后端为 Beta，仅仿真 HTP V68，支持量化 8-bit 网络。
- 需要已安装的 Hexagon SDK **5.0.0.0**；该文档说明近期 Hexagon SDK 不再附带 Hexagon QEMU，其他版本不保证可用。
- VTCM 限制为 4 MB；不支持 QnnMem、QnnSignal 及自定义算子包注册。
- Linux 主机后端使用 `lib/x86_64-linux-clang/libQnnHtpQemu.so`，DSP 驱动使用 `lib/hexagon-v68/unsigned/libQnnHtpV68QemuDriver.so`。

按对应版本文档配置 Hexagon SDK、QNN 环境、`QNN_DSP_EMULATOR_DRIVER` 和 `QNN_HTP_QEMU_ARGS`，准备适用的 V68 context 后，运行形式为：

```bash
qnn-net-run \
  --backend "${QNN_SDK_ROOT}/lib/x86_64-linux-clang/libQnnHtpQemu.so" \
  --input_list <input_list> \
  --retrieve_context <serialized_bin>
```

这是一条单独的 Linux 模型仿真流程，不能直接运行本包的 Android ADB 探针。包中存在 QEMU Driver 不代表仿真环境已经完整安装。其他 QAIRT 版本应核对随包文档，不将上述依赖条件无条件推广到所有版本。

仿真可检查受支持模型的功能与输出；无法证明真实 SA8295 的 Android FastRPC 驱动、DSP 固件、签名/权限、内存共享路径及性能可用。当前 V73 设备可验证 V73 链路和脚本流程，V68 包最终仍需 V68 实机验收。

Qualcomm 另提供 [Hexagon QEMU 测试项目](https://github.com/qualcomm/qemu-hexagon-testing)，含 V68 指令/程序测试示例；它不等同于已配置完成的 QNN HTP QEMU 环境，也不能替代目标板验收。

1. 新 V68 包从 QAIRT 2.46.0.260424 复制实际 V68 资源，共 26 个运行/ADB 文件；大小及 SHA-256 校验通过，脚本帮助和本地校验入口可用。

3. 使用临时 V73 对照脚本及原 V73 资源，在该设备上通过架构查询和 Calculator 测试，验证新脚本正常通过的执行分支；当时原 V73 包未修改；2026-09-13 仅将其 ADB 入口改为系统 PATH。
