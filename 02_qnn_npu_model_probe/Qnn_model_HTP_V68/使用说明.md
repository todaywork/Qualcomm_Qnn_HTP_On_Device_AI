# V68 模型探针使用说明

本包由同级 Qnn_model_HTP_V73 适配而来，面向 Android arm64 / Hexagon V68。

## 运行

双击 check_npu_model.bat。电脑需能执行系统 PATH 中的 adb.exe，使用系统 Python 3.10 或更新版本，运行检测不需要安装 NumPy、NDK 或 QAIRT。

```powershell
# 仅校验本地资源，不访问设备
.\check_npu_model.bat --check-files

# 单设备运行
.\check_npu_model.bat

# 指定 V68 设备；替换 V68_DEVICE_SERIAL
.\check_npu_model.bat -DeviceSerial V68_DEVICE_SERIAL -NoPause
```

运行时先校验清单，再使用系统 ADB。删除固定设备目录 /data/local/tmp/qnn_npu_model_probe 前检查路径及符号链接，重新创建并 push；任何步骤失败即停止。同一设备不要并行运行多个模型探针。

部署后使用 qnn-platform-validator 查询实际 DSP 架构，仅确认 V68 后才执行模型。当前 V73 设备不能作为 V68 实机验证通过依据。

## 模型与资源

- QNN 主机运行库、qnn-net-run、validator 来自 QAIRT 2.46.0.260424。
- Stub 为真正的 libQnnHtpV68Stub.so，DSP 文件全部来自 SDK lib/hexagon-v68/unsigned。未将 V73 文件改名冒充 V68。
- 复用原包的 Android arm64 libconv_relu_quantized.so 和两组输入。它通过 QNN 接口在运行时构建 Conv2d + ReLU 图，不是 V73 专用序列化 context，因此本次不重新编译模型库。
- 同一量化模型分别用 HTP 和 CPU 执行两组输入，检查完成次数、后端元数据，再比较输出。
- 每组输出 710432 个 float32；容差沿用原包 2 × 0.0547085 + 0.000001 = 0.109418。这是样例选定的绝对误差容差，并非通用精度标准。
- 不包含原 V73 的历史运行日志，也不附带 ADB；76 个运行/输入/脚本文件的来源及 SHA-256 登记在 bundle_manifest.json。

## 验证状态

本地文件与来源校验通过；BAT 帮助、本地校验入口可用。未完成 V68 实机推理测试，清单标记为 NOT_VERIFIED_ON_V68。原 V73 包保持不变。

日志在 probe_logs/时间戳。架构错误、ADB 失败、推理失败、元数据不符或输出超过容差都不能报告 PASS。最终 PASS 仅说明此模型在当前设备 shell 环境下完成 HTP 推理及 CPU 对照，不代表所有模型或 APK 均可运行。
